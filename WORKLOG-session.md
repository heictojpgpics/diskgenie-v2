Stage Summary:
- engine.rs: v3 dupes engine — XXH3-128-only (no SHA-256 authority pass), one-open-per-file screens (prefix + 2 mid windows A+B in a single open via `open_seq` with `FILE_FLAG_SEQUENTIAL_SCAN`), and **lockstep chain-partition verification** where each member streams 4 MiB blocks into its own `Xxh3` chain seeded with the bucket's shared screen digests, then `live.drain(..)` partitions by `chain.digest128()` every round (singletons retire early; ≥2 EOF = verified group). Two rayon pools via `OnceLock` (screen 8-24 threads latency-bound, verify 2-8 threads bandwidth-bound). `par_iter` is over BUCKETS in verify — each bucket is processed single-threaded inside.
- commands/dupes.rs: Tauri seam — three `#[tauri::command]`s (`find_duplicates` async + license gate + spawn_blocking; `dupes_status` sync re-attach query; `cancel_duplicates` sync generation bump) plus a 200 ms ticker thread emitting `dupes-progress` events. `compute_dupes` walks the tree single-threaded, calls `engine::run`, then **sequentially opens every verified member again** for `hardlink_identity` (the bottleneck — 3rd open per file). App-lifetime `DupesStatus` survives tab switches via `AppState.dupes_status` mutex.
